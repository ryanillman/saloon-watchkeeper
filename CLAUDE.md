# Saloon Watchkeeper (repo directory: boat-instruments)

ESP32-S3 touch-display marine instruments (LVGL, ESP-IDF v5.5.1, Signal K). Components are in `components/`; a Linux simulator and host tests are in `sim/` and `tests/`. README.md is the public document (what it is, simulator, build, config) and carries no bench specifics. The bench-board details are below; `docs/testing.md` has the live scenarios and what each should show.

## Working here

- Host tests: `cmake -S sim -B build/sim -G Ninja -DBUILD_TESTING=ON && cmake --build build/sim && ctest --test-dir build/sim --output-on-failure`, then `tools/check-layering.sh`. Run them after any `components/` change.
- Firmware: `. ~/esp/esp-idf/export.sh` first, then `tools/build-firmware.sh` (every directory in `boards/`). A build directory made before 2026-11-03 needs `fullclean` (see `docs/hardware/boards.md`, Internal RAM).
- Bench boards: `tools/deploy.sh <tty>...` asks each board which it is (`tools/board-id.py` resets it and reads the board id from its boot log) and flashes the matching image, whatever the tty number; `--dry-run` only identifies. A blank chip cannot answer: pass `board=tty`. `tools/build-firmware.sh` writes merged images to `out/<board>.bin` (flash at 0x0). Hardware probe build: `idf.py -D BOARD=lcd7 -D BI_EXTRA=diag/probe.defaults -B build/lcd7-probe build`. This machine's usual ports are in `.claude/CLAUDE.md`.
- Live check: a local test Signal K server (address in `.claude/CLAUDE.md`; zones the tool creates stay). `tools/scenario.sh up` starts the boat, a daemon that sends routine values for every covered path; `tools/scenario.sh` lists overlays and `tools/scenario.sh <name>` plays one on top (a unique prefix is enough); `down`, `status`, `log`, `zones`. Alarms are never written as notifications: the boat checks the path's zones, creates defaults if there are none, and drives the value across a boundary so Signal K raises and clears it. The exception is the emergency natures (`mob`, `fire`, `flooding`, `sinking`, `emergency`): they have no zone to cross, so the `emergency-mob`, `emergency-mob-nopos` and `emergency-fire` overlays use the `notify` op, which sends the notification as a delta. See `docs/signal-contract.md`. `alarm-coolant` raises at 10 s and clears at 40 s, so ACK within that window. `tools/sk-inject/live-check.sh` runs the raise/clear loop; `tests/sk_inject` (in ctest) covers the rest without a server.

## Alerts behaviour (`components/alerts`, `components/ui/src/ui_alerts.c`)

- The banner shows only un-acknowledged `alarm`/`emergency`. An acknowledged one moves to a bell-and-count marker in the top strip; the alert/warn count stays a separate amber marker. Both open the same list, which still lists acknowledged alarms (ACK hidden, state dimmed).
- Exception: an alarm whose ACK did not reach Signal K (`send_failed`, e.g. source down or no `ref`) stays on the banner, steady, showing `ACK NOT SENT`. Tests that ACK an alarm and expect the banner to clear must give it a `ref` and have the source up.
