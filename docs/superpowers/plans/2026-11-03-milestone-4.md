# boat-instruments Milestone 4 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the Tanks and Power roles, Signal K alerts with acknowledge and silence, and palette and brightness control, on every board and in the simulator.

**Architecture:** Roles gain instance groups so one role can read several device kinds. Power's arithmetic lives in a pure, tested `power_calc.c`. A new `alerts/` component holds the normalized alert list; `source_sk` feeds it and sends acknowledge and silence; `ui/` draws the banner, list, and markers from a snapshot each tick. Palette and brightness are driven by `app`, which owns config saving.

**Tech Stack:** C11, ESP-IDF 5.x, LVGL 9, cJSON, Unity host tests, SDL simulator, Python injector.

**Spec:** `docs/specs/2026-11-03-milestone-4-design.md`, extending `docs/specs/2026-11-02-boat-instruments-design.md`.

## Global Constraints

- `roles/`, `ui/`, and `alerts/` include no ESP-IDF headers. `tools/check-layering.sh` passes after every task; extend it to cover `alerts/`.
- Sources write `boatdata` and `alerts`; roles and UI only read (UI may queue acknowledge and silence requests through `alerts`).
- A missing value never looks like a reading: fault flag (`<LABEL> FAIL`), never a dash, blank, or 0.
- Every LVGL call happens on the UI task. No LVGL call from a network callback.
- boatdata stays SI. Conversion happens only when drawing, via `units_from_si`.
- Power paths are the default signalk-venus layout in the spec's Groups table. They are corrected after the bench Cerbo capture, not before.
- Each task ends with `ctest --test-dir build/sim --output-on-failure` and `tools/check-layering.sh` passing, then one commit.
- Commit messages are short imperative sentences in the existing style ("Add the Tanks role"), ending with the attribution trailer.

## Review Focus

1. **More than 16 active notifications.** A busy server can exceed the list. Expect the least severe entry to be dropped for a more severe one, never an alarm dropped for a warn. Test in Task 6.
2. **ACK pressed while Signal K is offline.** Expect the local state to change and the banner to read `ACK NOT SENT`, with no crash and no request left queued for a later connection. Test in Task 7.
3. **A device that appears after boot in any group** (an MPPT that wakes at dawn, a tank sender reconnected). Expect a rebind and rebuild, as engines get today. `app.c`'s `instances_changed` only compares one prefix. Test via `role_binding_same` in Task 2.
4. **A 96-character alert message.** Expect the banner text to wrap or truncate inside the banner, with ACK, SILENCE, and GO still visible and tappable. Snapshot in Task 8.
5. **A tank whose level goes invalid while capacity stays valid.** Expect `currentLevel` and the computed volume both to flag; the volume must not be computed from a stale level. Test in Task 3.

  bool batt_ok;  double batt_w;     // primary bank, + charging

  bool soc_ok;   double soc;        // ratio 0..1

// Sources: solar, charger, dcdc, alternator instances, flattened. batt: the primary bank.
// dc_system: the Cerbo's DC system power sample, or NULL.
power_summary_t power_summarize(const power_src_t *src, size_t n, const power_src_t *batt,
                                const bd_sample_t *soc, const bd_sample_t *dc_system,
                                int64_t max_age_ms, int64_t now_ms);

// Index of the primary bank: the instance whose id equals `primary` if non-empty and present,
// else the first with a stateOfCharge path bound (soc_bound[i]), else 0.
uint8_t power_primary(const char ids[][24], const bool *soc_bound, uint8_t n, const char *primary);

typedef enum { TTG_VALUE, TTG_CHARGING, TTG_FAIL } ttg_mode_t;
ttg_mode_t power_time_remaining(const bd_sample_t *ttg, const bd_sample_t *current, int64_t max_age_ms, int64_t now_ms);
```

typedef enum { AL_NORMAL, AL_ALERT, AL_WARN, AL_ALARM, AL_EMERGENCY } alert_state_t;   // same order as SK_STATE_*
typedef enum { AL_REQ_NONE, AL_REQ_ACK, AL_REQ_SILENCE } alert_req_t;

  int64_t since_ms;
} alert_t;
typedef struct { alert_t a[ALERTS_MAX]; uint8_t count; bool source_up; } alerts_snapshot_t;   // sorted: most severe first, then newest

void alerts_init(void);
void alerts_upsert(const char *id, alert_state_t st, const char *msg, bool audible, int64_t now_ms);   // AL_NORMAL clears
void alerts_clear(const char *id);
void alerts_source_up(bool up);                 // false clears the list
void alerts_snapshot(alerts_snapshot_t *out);
alert_state_t alerts_for_path(const char *path);   // highest active state whose id equals path; AL_NORMAL if none

// UI side: mark locally and queue for the source. Dropped (send_failed = true) when the source is down.
void alerts_request(const char *id, alert_req_t req);
// Source side: next queued request, if any. Queue holds 8; oldest dropped and marked send_failed on overflow.
bool alerts_next_request(char id[64], alert_req_t *req);
void alerts_request_result(const char *id, bool ok);

// Buzzer pattern, pure: true while the buzzer should sound at now_ms.
bool alerts_buzzer_on(const alerts_snapshot_t *s, bool enabled, int64_t now_ms);   // alarm: 200 on / 800 off; emergency: 150 on / 150 off
```
- Semantics: a state escalation (warn → alarm) or a re-raise after a clear resets `acked`, `silenced`, and `since_ms`. The same state repeated keeps them. Acknowledge sets `acked` (stops flashing and buzzer); silence sets `silenced` (stops buzzer only).
